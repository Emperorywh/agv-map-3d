# 道路视觉重构

视觉采用工业导视：灰蓝道路包络、连续白色边线、清晰蓝色真实轨迹与稀疏路口光点。全部原始物理路径均显示，接入线不再因分类被省略路面或降低可见度。黄色标线、红白方向箭头仍保持移除；业务节点的类型、位置和近景显示机制不变。

## 数据边界

原始地图没有主路、支路或车道宽度字段。以下分级是独立的展示规则，不是调度道路等级，不用于寻路、安全间距或通行能力判断。

- `warehouse`、`charge`、`park` 的接入路径保留接入角色，但与支路一样绘制路面和边界。
- 排除上述路径后，从库位角色末梢沿二度节点追踪，总长度不超过 3 米的短链标记为接入角色。该角色不再隐藏路面或弱化引导线。
- 其余路径通过实际端点切向匹配互为最佳、偏转小于 20° 的延续，连续弧长达到 12 米时显示为主通道；其余为支路。
- 主通道包络宽 1.5 米，支路及接入路径包络宽 0.8 米，仅是视觉尺寸。所有路径统一使用宽 0.065 米、透明度 0.9 的蓝色引导线。相邻包络只为消除内部白边而合并，不因此筛掉轨迹或新增逻辑连接。
- 调度边的方向、反向属性、限速、采样点和有向出边索引均保留。蓝色引导线不表示单向或双向。

所有尺寸与颜色集中在 `src/features/map-visualization/scene/mapAppearance.ts`。`buildMapGeometry` 的可选第三参数允许按逻辑边 ID 提供 `ReadonlyMap<string, 'main' | 'branch' | 'access'>`，显式配置优先；同一物理路径的正反向配置冲突时采用较窄级别。该入口是构建层能力，当前未接入运行时配置或界面控件。

## 几何与资源

道路包络直接遍历全部物理路径生成，不再依赖合并链筛选。`roadTopology.ts` 的链仍用于诊断，交叉节点用于筛选光点。使用 Clipper 的整数多边形并集裁掉路口内部边界，再从外环和孔洞生成白色边线；蓝色引导独立按每条真实路径绘制，不参与全局轮廓合并。包络计算精度为 0.1 毫米，量化不回写原始轨迹。

道路分为四份静态合批：路面、白边、蓝色引导、路口光点。地图运行时统一释放几何，图层仅释放自己创建的材质；不新增逐帧道路计算、光源或动画。旧 `pathArrowMaterial.ts`、`pathMarkingLayout.ts` 已删除，节点限径逻辑迁入 `nodeMarkerLayout.ts`，旧代码可从 Git 历史恢复。

## 验证

运行 `pnpm verify:roads`，覆盖分级、短库位接入与长巷道、覆盖冲突、正反向去重、十字路口裁剪、平行路径、闭环孔洞、急弯与退化输入、贝塞尔、全接入图、完整真实地图不变性和幂等释放。新增全图几何覆盖检查：每条物理路径的所有采样点及每段中点都必须落在最终路面和引导线三角形上，不能只用索引数量证明“已显示”。测试复用项目 Vite 别名，独立缓存避免干扰开发页面。

另执行 `pnpm typecheck`、`pnpm lint`、`pnpm build`，并在浏览器中检查实际地图与转弯近景。
