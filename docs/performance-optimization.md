# 本轮性能优化

默认使用 `public/config.json` 中的 `renderer.qualityPreset: "balanced"`。修改配置并刷新页面即可切换档位；省略该字段的旧部署也采用均衡档。车辆容量、告警、坐标和数据源均不受档位影响。

## 画质预算

| 项目 | performance | balanced（默认） | high |
| --- | --- | --- | --- |
| DPR 档位上限 | 1 | 1.25 | 2 |
| 离屏 MSAA 上限 | 0 | 2 | 4 |
| Bloom 首层边长 / 主画面 | 1/4 | 1/2 | 1 |
| 透射采样边长比例 | 0.35 | 0.5 | 1 |
| 反射尺寸 | 256² | 512² | 1024² |
| 静止镜头反射刷新上限 | 15 Hz | 30 Hz | 60 Hz |
| 实时点光源上限 | 4 | 8 | 64（不超过塔数） |
| 车辆模型 | 三档 LOD | 三档 LOD | 原精修模型 |
| 充电塔、地面与车载货架 | 三档 LOD | 三档 LOD | 原精修模型 |
| 主画面水晶真实透射 | 整塔投影约 180 CSS 像素以上 | 整塔投影约 120 CSS 像素以上 | 始终保留 |
| 倒影水晶 | 简化半透明材质 | 简化半透明材质 | 简化半透明材质 |

实际 DPR 取设备 DPR、原有 `renderer.maxDpr` 和档位上限的较小值；实际 MSAA 同时受设备能力限制。方向光阴影继续使用原有 `renderer.shadowMapSize`，默认 2048。相机移动时反射立即采集，避免复用旧视角产生明显拖影；静止镜头下按预算定期采集，车辆倒影不会冻结。

`high` 用于保留主画面精修细节及较高采样质量，不是旧版本逐参数回滚。三档都保留 CPU 更新、拾取、顶点索引优化、灯槽稳定化，以及倒影中的水晶简化。

## 车辆模型

使用本机 Blender 5.2 后台从 `public/models/AGV_FUTURE.glb` 生成独立派生文件，原资产未修改。生产构建使用 Three.js r185 GLTFLoader 验证了三档的材质分区、顶点属性及包围盒。

| 模型 | 三角形 / 台 | GLB 字节 | 相对原模型减少 |
| --- | ---: | ---: | ---: |
| AGV_FUTURE.glb | 58,732 | 960,984 | — |
| AGV_FUTURE_LOD1.glb | 13,300 | 272,300 | 77.4% 三角形 |
| AGV_FUTURE_LOD2.glb | 5,061 | 135,636 | 91.4% 三角形 |

均衡档以整车约 2.8 米投影直径作为统一估算口径：大于约 120 CSS 像素使用精修模型，36～120 像素使用中景，小于约 36 像素使用远景；性能档阈值分别为 180 / 60。切换有 15% 滞回，各渲染相机分别维护状态。数值指包络估算，不是逐像素精确轮廓。

三档几何共享原始材质、业务槽位与位姿；减面资产不重新缩放或调整定位原点。低模文件不可用时回退到精修模型。灯带和小部件保留最低面数，降低状态识别特征消失的风险。资产减面比例不能直接等同于 FPS 提升比例。

## CPU 与交互

- 车辆矩阵和颜色分别记录脏槽位；提交和活跃计数不再扫描整批 256 个槽位。批内数据纹理的上传范围仍受 Three.js 实现控制，此处不宣称已实现 GPU 纹理局部上传。
- 模型按材质合并时保留索引，按位置和法线共同去重，保留法线接缝。
- 标签观察运行时版本、相机、窗口、槽位表及选择状态。输入不变时跳过计算；普通隐藏车辆不做屏幕投影，候选排序与碰撞容器复用，仍保留原有前二十候选预算。
- 可拾取部件改用精修几何的局部包围盒代理。点击、悬停和双击继续返回同一车辆槽位；包围盒边角可能比实际模型轮廓稍宽，不提供三角形级命中。
- 充电塔使用固定数量点光源槽，未分配槽强度为零；镜头变化时按视野贡献和距离重新分配。全部塔保留自发光及柔和地面光斑。灯位切换有优先级滞回，灯槽数量不随镜头变化，减少着色器变体。

## 设施与多通道优化

针对约 10 FPS、1493 万三角形及 775 次绘制的反馈，增加设施 LOD 和透射预算。以下为交付资产的实际三角形数量，原始文件未修改；低模由 `scripts/buildFacilityLods.py` 使用 Blender 5.2 从原文件独立生成。

| 设施 | 原模型 | 中景 LOD1 | 远景 LOD2 |
| --- | ---: | ---: | ---: |
| 充电塔 | 40,218 | 9,350 | 4,072 |
| 空货架 | 3,580 | 787 | 221 |
| 满载货架 | 23,614 | 5,188 | 1,319 |

当前本地地图包含 59 座塔、48 个空架和 48 个满载架。这些设施全部使用远景几何时，单次绘制合计从 3,678,174 面降到 314,168 面，约减少 91.5%。这是资产数量预算，实际帧统计还取决于视锥、LOD 分布和渲染通道，不能等同于 FPS 提升幅度。车载满载架也使用相同 LOD，不再在远景车辆上固定绘制 23,614 面载荷。

- 地面货架按十二米网格分批，再按每个绘制相机逐实例剔除；近景不再因少量可见货架提交全地图实例。分块会增加批次数与数据纹理数量，应结合完整帧耗时和三角形评估，不能仅比较资源对象个数。
- 塔体先按材质与顶点布局合成整塔部件，再逐塔合批。近景几何和材质保持原样，不透明批次关闭逐部件排序。
- 车辆与设施共用投影 LOD 规则。主画面保留原 CSS 像素口径，透射与倒影按实际视口折算；不同相机和分辨率分别保存 15% 滞回。均衡与性能档中，阴影和倒影最多使用中景几何。
- 水晶近景保留原始双面透射材质，远景使用保留颜色与自发光的单次绘制半透明标准材质。倒影采集前暂时替换水晶材质，采集后或异常时恢复，避免倒影再次触发水晶透射预通道；近景画面仍可能包含主透射预通道。
- 水晶几何不减面，复杂网格减面后若小材质分区不足，会提高该网格的保留率。生产构建校验全部设施三档的材质、顶点布局、有限属性、内嵌图像字节范围和三厘米尺寸容差；构建不解码贴图像素，贴图显示由浏览器验收。
- 原有实时反射刷新规则保持：镜头移动立即更新，静止镜头按时间预算采集。10 FPS 下即便限制 15/30 Hz 仍可能逐帧采集，本轮主要减少每次采集的模型和透射负载。

## 性能观察

使用生产构建 `pnpm build`、`pnpm preview`。在网址加入 `?perf=1`（已有查询参数时用 `&perf=1`），打开控制台读取：

```javascript
// 每秒发布最近采样窗口的完整帧指标，不逐帧刷控制台。
// cpuSubmitMs 是同步 CPU 提交耗时，不是 GPU 执行耗时。
console.table(window.__AGV_PERFORMANCE__)
```

包括 FPS、平均帧间隔、P95 帧间隔、CPU 同步提交耗时、平均完整帧绘制调用及三角形数量，以及几何、纹理、程序数量和 multi-draw 扩展支持。完整帧计数包含反射、阴影、透射及后处理，不能与只读取最后一个通道的旧统计直接比较。关闭 `perf` 参数即可停用采样。后台恢复或超过 250ms 的帧间隔会重置采样窗口，因此该统计用于稳定运行对比，不代替启动卡顿或长任务分析。

建议固定窗口、车辆数量及镜头，在总览、近景、拖拽和悬停四种情况下分别比较。切换画质档后等待加载和着色器预热完成再观察。可重点检查远近切换、近景灯带、车辆载荷、前后车选择、告警标签、移动倒影和资源重建后的状态。

## 验证与范围

本轮执行 `pnpm lint`、`pnpm typecheck` 和 `pnpm build`，生产构建包含车辆与设施三档 GLB 的发布检查；未新增单元测试，未运行自动格式化。新增、修改逻辑提供多行简体中文注释。画面验收按项目规则由使用者完成，尚未取得真实浏览器 FPS 对比，不能承诺具体帧率增幅。对照时重点观察总览和局部货架面数、近景水晶切换、移动车辆倒影、车载货架标签，以及上下文恢复后的设施完整性。

本轮保留对数深度缓冲、动态阴影及前台连续渲染，避免直接改变远墙/道路深度关系或冻结动态车辆与状态灯。阴影缓存、深度模式替换、Worker、WebGPU 和烘焙光照尚未纳入本轮；后续根据完整帧统计确定是否需要继续。
