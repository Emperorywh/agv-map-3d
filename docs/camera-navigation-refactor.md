# 相机交互重构

## 问题机制

旧实现由 OrbitControls 捕获指针、自定义 Hook 保存另一份拖动状态。左键与右键关闭了原生动作，但中键、触摸和指针生命周期仍属于原生控制器；捕获、失焦和鼠标多键切换容易使两边对当前手势的理解不一致。

右键平移还存在两个独立的输入丢失路径：前后两条射线任意一条不能命中地面，就直接返回；产生位移后又按整幅画面的视锥包络推回观察中心。后者把自动取景要求施加于持续平移，低角度下可移动范围会被远处的画面边缘大幅压缩。旋转试算同时修改相机和控制器限值，进一步增加了连续操作对前一次状态的依赖。

这些结论来自源码审查；未通过浏览器实操确认用户现场由哪条路径触发。

## 新的数据流

`鼠标事件 → bindNavigationInput → createGroundNavigation → 空间约束 → 相机矩阵`

- `bindNavigationInput` 独占鼠标会话和指针捕获，处理按键交接、画布外释放、捕获丢失、窗口失焦、滚轮单位和空格键。
- `createGroundNavigation` 每次从真实机位计算旋转、平移和缩放。地面求交不稳定时，平移改用相机的水平基向量与当前观察比例。
- `createCameraNavigationController` 是机位提交的唯一入口，不再实例化 OrbitControls，也不通过 change 事件嵌套修改相机。
- `useCameraNavigation` 只管理自动取景、跟随目标、公开命令及挂载清理，高频位姿不写入 React 或 Store。

## 操作与边界

| 操作 | 行为 |
| --- | --- |
| 左键拖动 | 改变角度，正常范围内保持按下处的地面落点 |
| 右键或修饰键加左键拖动 | 地面平移，近景使用当前缩放比例 |
| 滚轮 | 自由浏览绕光标缩放；跟随车辆时绕观察中心缩放 |
| 中键拖动 | 使用同一缩放通道 |
| 拖动期间滚轮 | 立即缩放并更新屏幕基准，继续当前手势 |
| 空格 | 退出跟随并总览；输入框、按钮及组合快捷键不被拦截 |

自动监控取景与总览继续使用原有视锥算法。手动浏览约束相机位置、观察中心、俯角和离地净空，允许屏幕边缘看到厂房外侧。触边只截断越界坐标，保留沿墙方向；必要的边界修正优先于光标落点锁定。

调试与预览引用改为公开的 `CameraNavigationControls` 类型，保留 `target`、距离配置和 `update()` 入口；它不再是第三方 OrbitControls 实例。

## 自测重点

按仓库 AGENT.md，不新增单元测试或测试依赖，代码质量通过 `pnpm lint`、`pnpm typecheck`、`pnpm build` 检查。实际鼠标手感由使用者验证：

1. 左键改变水平和俯仰角，连续滚轮放大，再在画布不同位置右键横向、纵向和斜向拖动。
2. 低角度近景中拖到边界，沿墙移动，再反向拖动。
3. 拖出画布松键、切走窗口再返回、左键和右键交替按住，确认没有残留拖动。
4. 拖动中使用滚轮，确认松手即停；拖出再回到原点不误选车辆。
5. 双击跟随车辆后缩放，拖动退出跟随，按空格回到总览。
